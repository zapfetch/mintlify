如果你现在跑在 Firecrawl Cloud（`api.firecrawl.dev`）上，迁移到 ZapFetch
是**直接替换**：换一个 Base URL、换一个 API Key，上线。**不需要重构任
何业务代码**，**不需要换 SDK**，**不需要改 schema**。ZapFetch 与 Firecrawl
的 `/v1/*` 和 `/v2/*` 端点做到了字节级兼容。

## ZapFetch vs Firecrawl Cloud 对比

| | Firecrawl Cloud | ZapFetch |
| --- | --- | --- |
| API 端点 | `/v1`、`/v2` | `/v1`、`/v2`（字节级兼容） |
| SDK | `firecrawl-py`、`@mendable/firecrawl-js` | **沿用同一套 SDK**——只改 `api_url` |
| 计费 | 美元、有起订量 | 美元、**无起订量、无承诺消费** |
| 边缘节点 | 默认 US-east | **新加坡节点**，亚太原生 |
| 格式倍率 | Markdown + HTML + 截图 = 多次扣费 | 所有格式包含在 **1 credit** 里 |
| 失败请求 | 计费 | **免费**——4xx、5xx、超时、robots.txt 拦截 |
| Crawl 计费 | 按已下发页数 | 按**成功抓取**的页数 |
| 厂商锁定 | 必须用厂商 SDK | 沿用 `firecrawl-*` 标准 SDK，**零锁定** |

迁移共三步——Base URL、Key、可选的 client 配置——大多数应用 10 分钟内完成。

## 为什么迁？

- **美元计费，按用量结算。** 无起订量、无承诺消费，用多少算多少；剩余
  额度会写在每次响应里。
- **SDK、Schema 都不变。** 继续用官方的 `firecrawl-py` 和
  `@mendable/firecrawl-js`，不锁定厂商，也不需要学新 SDK。
- **v1 与 v2 端点都兼容。** 不论你现有 SDK 用的是哪个版本，直接切过来
  就能跑。
- **亚太原生节点。** API 部署在新加坡，抓取 `.jp`、`.kr`、`.cn`、`.tw`、
  `.sg` 等域名的延迟更低，且较少触发地域屏蔽。

## 第一步 — 拿到 ZapFetch API Key

1. 用 GitHub / Google 账号或邮箱登录 [ZapFetch Console](https://console.zapfetch.com/dashboard)。
2. 进入 **Dashboard → API Keys**。
3. 点 **Create key**，复制生成的 UUID API Key。Key 只显示一次，请妥善
   保管。

> ZapFetch 当前生成的是 UUID API Key，不是 `fc-` 前缀的 Firecrawl Cloud
> Key。如果你的现有配置强制校验 `fc-` 前缀，请先放宽这个校验再切流量。

## 第二步 — 把 Base URL 指向 ZapFetch

把 SDK / HTTP 客户端里的 Firecrawl 域名替换成 `https://api.zapfetch.com`。

### curl

```diff
- curl -X POST https://api.firecrawl.dev/v1/scrape \
+ curl -X POST https://api.zapfetch.com/v1/scrape \
    -H "Authorization: Bearer YOUR_ZAPFETCH_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{ "url": "https://example.com", "formats": ["markdown"] }'
```

### Python

```diff
  from firecrawl import FirecrawlApp

- app = FirecrawlApp(api_key="YOUR_ZAPFETCH_API_KEY")
+ app = FirecrawlApp(
+     api_key="YOUR_ZAPFETCH_API_KEY",
+     api_url="https://api.zapfetch.com",
+ )
```

### Node.js

```diff
  import FirecrawlApp from "@mendable/firecrawl-js";

- const app = new FirecrawlApp({ apiKey: "YOUR_ZAPFETCH_API_KEY" });
+ const app = new FirecrawlApp({
+   apiKey: "YOUR_ZAPFETCH_API_KEY",
+   apiUrl: "https://api.zapfetch.com",
+ });
```

## 第三步 — 换成 ZapFetch 的 Key

把环境变量里的 Firecrawl Key 替换成第一步拿到的 ZapFetch Key：

```diff
- FIRECRAWL_API_KEY=firecrawl-key-here
+ FIRECRAWL_API_KEY=zapfetch-uuid-key-here
```

## 冒烟测试

跑一次 scrape 验证迁移成功：

```bash
curl -X POST https://api.zapfetch.com/v1/scrape \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "url": "https://example.com", "formats": ["markdown"] }'
```

预期：HTTP 200 + `data.markdown` + 剩余额度信息。

## 切流期间双跑

两边的 Key 互不干扰，可以同时跑——ZapFetch Key 走 `api.zapfetch.com`，
Firecrawl Key 继续走 `api.firecrawl.dev`。建议按比例切流：先把 10% 流量
打到 ZapFetch，对比一两天的成功率和 markdown 输出，再逐步加大比例。
没有强制注销 Firecrawl 账号的要求，可以保留一个计费周期作为兜底。

## 常见问题

### ZapFetch 是真的"直接替换"Firecrawl 吗？

针对 Firecrawl Cloud 的 API 是的。`/v1/*` 和 `/v2/*` 全部端点——
`scrape`、`crawl`、`search`、`map`、`extract`——请求和响应 schema 一一
对应。现有读 `creditsUsed`、`remainingCredits` 的客户端代码无需改动。
如果发现行为差异，当 Bug 反馈即可。

### 价格对比怎么样？

ZapFetch 美元 credit 计费。失败免费、无格式倍率、Crawl **按成功抓取
的页数计费**（不是下发页数）。当前计划见 [Billing](/zh/billing)；订阅
权威数据在 `console.zapfetch.com/dashboard/billing`。

### 限流呢？

见 [Rate limits](/en/rate-limits)（中文版规划中）。Free 计划默认配额
够大，付费计划等比放大。`429` 响应带 `Retry-After`，现有 SDK 的重试
逻辑无需改动。

### 可以两边并行跑吗？

可以。两个 Key、两个 Base URL 完全独立。多数团队按端点切流——一次切一
个，留 Firecrawl 兜底一个计费周期。

### 为什么 ZapFetch 抓亚太站点更快？

API 边缘在新加坡，抓 `.jp`、`.kr`、`.cn`、`.tw`、`.sg` 域名只走一跳
区域内路由，不必绕回 US-east。在懒加载多请求的电商站点 Crawl 上，这
个延迟优势会被放大。
